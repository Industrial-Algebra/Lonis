# ADR-0010: v0.2 additive wire — typed identity seam, verification tier, no-match contract

- Status: accepted
- Date: 2026-08-29
- Branch: `feature/v0.2-typed-seam`
- References: PULSE_2026-08-27_Lonis §6 ("namespaced-string convention + trait
  validation seam" — the wire-preserving option); Lonis PR #21 recommendations
  R2 (verification tier) and R7 (no-match contract) verbatim; in-house
  precedent `ToolId` (lonis-schema/src/lib.rs:148 — the exact newtype
  pattern mirrored here); ADR-0008 (replay evidence); Ijima memory promotion
  ladder (`persona:{id}` namespaces, AutoCapture → promote)

## Context

v0.1 shipped attribution as a bare `String` `identity`, an unverifiable
"trust-me" slot: nothing could distinguish a registry-owned participant
(`persona:sara`) from an arbitrary blob, and no vertical had a hook to
validate what it was given. Two further gaps came out of the discovery
substrate review (PR #21): discovery catalogs had no curation status (a
machine-extracted entry is not the same commitment as a human-adopted one),
and search-capable verticals returned silent empties on zero results —
"nothing exists" and "your phrasing was wrong" were indistinguishable.

The design constraint governing every change: the v0.1 wire generation is
frozen. Any 0.2 emission with the new fields unset must be byte-identical to
its 0.1 form, so the entire 0.1 ecosystem keeps working unchanged.

## Decision

Three additive changes, all wire-preserving:

1. **Typed identity seam.** New `lonis-identity` crate providing
   `ParticipantId`, a namespaced `source:slug` newtype (`persona:sara`,
   `agent:pi`, `lonis:test:golden`) mirroring `ToolId`'s validation rules
   (at least two non-empty `:`-separated segments), and the
   `IdentitySource` trait — the validation seam registry owners implement
   for the sources they own. `Attribution.identity` changes type from
   `String` to `ParticipantId` on the Rust side only: `#[serde(transparent)]`
   means it serializes as the identical bare string, so the wire form is
   unchanged. `Attribution::new` keeps its shape (`impl Into<ParticipantId>`)
   and `From<&str>`/`From<String>` (no validation — the parsing trust
   boundary is `new()`) keep existing call sites compiling unchanged.
   `lonis-schema` re-exports `ParticipantId`, `ParticipantIdError`, and
   `IdentitySource` so verticals reach the seam through one crate.
2. **Verification tier (R2).** `Verification` enum
   (`curated | auto_extracted | probed`) as an **optional** field on
   `ToolContract` (last position, `#[serde(default, skip_serializing_if =
   "Option::is_none")]`) — the payload surface discovery tools expose. Unset
   ⇒ serialized form identical to 0.1.
3. **No-match contract (R7).** `NoMatchDiagnostic` + `ScoredNeighbor`
   contract types. Search-capable verticals MUST return a
   `NoMatchDiagnostic` on zero results, never a silent empty — with the
   nearest candidates and the ranking basis so the miss is diagnosable.

Wire generation stays **v1**: `Block.schema_version` /
`BLOCK_SCHEMA_V1` / `protocol_version` in `schemas/*.json` are frozen; crate
semver moves to 0.2.0 only. New fields are all option-shaped with
skip-serializing-when-unset; `deny_unknown_fields` is untouched.

### Reserved sources

Source prefixes reserved by the Lonis ecosystem (documented convention):

| Source   | Owner                                                        |
|----------|--------------------------------------------------------------|
| `persona`| Dominic persona registry (aligns with Ijima `persona:{id}` namespaces ADR) |
| `agent`  | Agent identities (e.g. `agent:pi`)                           |
| `tool`   | Tool identities (e.g. `tool:lonis:builtin:echo`)             |
| `human`  | Human operator identities                                    |
| `lonis`  | Lonis test/harness identities (e.g. `lonis:test:golden`)     |

Registry owners validate their own sources via `IdentitySource`; a
participant id whose source nobody owns is unvalidated, not invalid.

### Promotion evidence

The R2 ladder (`AutoExtracted` → promote → `Curated`) is the shared
ecosystem concept already named by Ijima's memory promotion
(AutoCapture → promote): "promotion evidence" is what moves an entry from
machine-extracted to human-adopted. `Probed` carries replay evidence
(ADR-0008) — a successful replay's hash pins the entry.

### No-match obligation

Search-capable verticals MUST return `NoMatchDiagnostic` on zero results —
echoing the query, reporting `matched: 0`, listing nearest candidates (if
any) with scores and basis, and a human/agent-readable sentence. Silent
empties are a contract violation: consumers can no longer tell "no such
concept" from "bad phrasing".

## Consequences

- The 0.1 wire generation is provably preserved: all 16 golden fixtures
  under `crates/lonis-schema/tests/golden/blocks/` remain byte-for-byte
  unchanged and the existing test suite stays green with zero fixture edits
  (wire-preservation proof in `tests/wire_v02.rs`).
- 0.1 readers reject 0.2 emissions **only** when the new fields are set
  (unknown fields / shapes); unset ⇒ indistinguishable from 0.1.
- `Attribution.identity` is now typed: call sites using `Attribution::new`
  compile unchanged; struct-literal sites add `.into()`; serializers see the
  same bare string.
- New crate `lonis-identity` (v0.1.0) is standalone — Dominic/Tsume/Wallace
  adopt it independently of the schema's cadence.
- Out of scope, fenced for future units: typing `AttributionSource.producer`,
  moving `ToolId` into `lonis-identity`, tolerant-reader changes, adapter
  work in amari-discovery/karpal/Dominic/Tsume/Wallace, RFC 8785/JCS study,
  new block kinds, CLI changes, fixture regeneration, and any search
  implementation (R7 ships the contract types + this obligation only).
